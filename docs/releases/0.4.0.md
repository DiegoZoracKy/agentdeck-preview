# AgentDeck 0.4.0 source candidate

AgentDeck 0.4.0 is the source candidate that reopens the original repository as
`agentdeck/agentdeck`. It is not yet a PyPI release: PyPI continues to serve the stable
0.2.0 package until a separate tagged release is approved.

## What changed since the published 0.2.0 release

### Execution truth is an independent kernel

Games, Players, Controllers, Spectators, Assembly, execution, canonical Records, and
replay form a reusable kernel that does not depend on Research. The redesign removed
the old study-specific pooling, scorer, profile, and packaging machinery from this
boundary instead of preserving it as compatibility surface.

### Research was rebuilt over immutable execution facts

Research is again a first-class AgentDeck capability, implemented downstream from the
execution kernel through a smaller set of explicit contracts:

- a `Study` describes the Question, semantic Conditions, and exact prepared execution
  references without duplicating Assembly authority;
- `StudyExecution` receipts bind canonical Records to Execution Groups, Assembly Runs,
  match slots, effective seeds, and Cells;
- a closed `RecordCorpus` identifies the exact execution facts used by analysis;
- deterministic `Measures` derive flat, addressable results;
- immutable `Evidence` binds a corpus, a Measure, and the declared Study scope;
- authored `Findings` cite exact Evidence results and remain interpretation rather than
  mechanically certified truth.

Every stochastic or intelligence-mediated observation that can affect Evidence must
cross the canonical Record boundary before deterministic derivation begins. The
execution kernel never imports the Research layer.

### Games expose Research possibilities without making claims

Versioned Game Research Profiles describe what a Game's mechanics make observable,
which Research Opportunities are plausible, which operationalizations are currently
supported, and which claims remain outside the instrument's boundaries. Profiles can
reference prepared Measures, but they cannot select a Measure, create a Study, override
an Assembly, or alter historical execution identity.

### The Agentic Edge is the end-to-end acceptance case

The current Research contracts materialize The Agentic Edge as a normal 19-Cell Study
with 540 planned Matches, two Game Research Profiles, and two ordinary Measures. The
reproducer reads the frozen public Hugging Face revision without mutating it, verifies
all 540 source Records against the pinned checksum manifest, adapts local copies to the
current Record schema, and preserves `source_sha256 -> adapted_sha256` provenance.

For the nine primary and supplemental Cells, the current pipeline derives Evidence
over 432 imported Records and reproduces 99 of 99 frozen outcome/statistical values.
The promoted behavioral Measure is also derived over the same identified corpus. The
historical source remains explicitly `imported`; it is never represented as execution
produced by the current Study or Assembly.

### Records preserve stronger provenance

Current Records preserve effective Game and Player configuration, a scoped Game
implementation fingerprint, provider-native SDK arguments and response metadata,
retained conversation selection, attempts, errors, stop reasons, costs, and state
transitions. Provider failures and incomplete or textless responses remain visible
instead of being collapsed into a generic failure.

### Controllers fail closed

Built-in Controllers require a line-anchored `ACTION:` field. Action-like words inside
reasoning or narration no longer become accidental moves. Requested treatment,
response-contract compliance, and resolved Game action are recorded separately.

### Provider-backed Players are explicit

Provider-backed Players require an explicit model instead of silently selecting a
default. OpenAI execution uses the Responses API, keeps system instructions separate
from provider configuration, validates model options, and permits provider-default
temperature when it is intentionally unset.

### Players can be human-controlled

`HumanPlayer` lets a local person participate through the same handshake, prompt,
Controller, canonical Record, and replay lifecycle as every other Player. The default
adapter is synchronous terminal input; an injected synchronous reader supports tests and
local integrations. Human-controlled execution does not fabricate model, provider,
token, retry, or per-Player pricing metadata and is intentionally serialized with
`concurrency=1`. Remote/asynchronous sessions and a generalized driver architecture are
not part of this release.

### Executable compositions can be prepared and sealed

Assembly resolves the concrete Game, Players, Controllers, Renderers, provider options,
and execution settings before a run. The prepared composition can be content-addressed,
authorized, and executed as the same sealed identity rather than reconstructed by a
host application.

### Interrupted execution preserves what actually happened

Provider-call custody journals persist requests and outcomes before downstream
use. Recovery exposes unresolved calls without silently retrying them or claiming
unknown charges are zero. The declared `LLMPlayer.max_retries` budget controls
OpenAI, Anthropic and Google attempts; SDK transport retries no longer multiply
that budget.

Single-player Games must declare an explicit parse-failure policy. ABORT stops
serial and parallel batches while preserving partial Records, completed work and
observed usage. Unexpected worker failures preserve the last observed state and
the original exception. Assembly and Study receipts remain inspectable after
initialization or execution failures, including when earlier runs succeeded.

### Runnable references cover the complete Research journey

Hidden Signal demonstrates information acquisition by one Player without a
winner. Reserve Courier supplies a small example Game, known-answer calibration,
optional Spectator and Monitor, varied configurations, replay, Measure, Evidence
and an authored Finding. Its optional eight-cell model smoke is a pipeline check;
one observation per cell does not establish a behavioral effect.

Reference acceptance checks preserve frozen probes and artifacts. A derived
source lock permits supported Python versions to verify the same authored
material while new Measure, Profile and Evidence identities retain the actual
Python version. Equal derived values across environments do not imply equal
artifact hashes.

## Compatibility

Users of 0.2.0 should treat 0.4.0 as a migration:

- import the current Game, Player, Controller, Assembly, Record, replay, and Research
  APIs;
- provide explicit models for provider-backed Players;
- update Controller output contracts to use an explicit `ACTION:` line;
- migrate old Research scripts to Study, RecordCorpus, Measure, Evidence, and Finding;
- do not assume compatibility with the removed `agentdeck-research-*` command family or
  the old scorer/pooling APIs;
- validate custom components against the current specifications and conformance tests.

Additional migration details:

- `MATCH_START` precedes handshakes so rejected or unavailable handshakes can
  leave truthful terminal Records; Spectators should follow the current lifecycle.
- Handle partial execution receipts and propagated abort/worker exceptions.
  Usage aggregates preserve known-cost subtotals when the full cost is unavailable.
- Resolve JSON CLI artifact paths through `data.output_root`; stdout contains one
  JSON envelope and diagnostic or Monitor output goes to stderr.
- `RenderResult.metadata` is an owned immutable JSON snapshot, including nested
  values. Construct a new result to change metadata.
- Review the [execution migration guide](../e2e-hardening-migration.md) and the
  [historical artifact provenance notes](../../research/PROVENANCE.md).

The 0.4 Research axis is a replacement built over the clean execution kernel, not a
restoration of every API removed after 0.2.0.

## Repository identity

The canonical repository is again `agentdeck/agentdeck`, preserving the original Git
history, research artifacts, specifications, releases, and authorship timeline. The
hosted product remains a separate private repository.

Reopening the repository does not publish 0.4.0 to PyPI. Packaging and release remain a
separate explicit decision after source validation.
