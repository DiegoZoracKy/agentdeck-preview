# AgentDeck Core 0.2.0

AgentDeck Core 0.2.0 is the honest public release for the package state that
was accidentally published as `0.1.3`. Version `0.1.3` should be treated as a
metadata correction release with an incorrect patch number; `0.2.0` carries the
same accumulated code surface under a version that reflects the schema and API
scope more accurately.

## Why 0.2.0

The public `0.1.3` package was built from current `main`, not from the code that
had previously shipped as `0.1.2` plus metadata-only changes. As a result, it
included roughly two months of unreleased Core work. Since PyPI files are
immutable, `0.2.0` supersedes `0.1.3` instead of attempting to reuse that
version number.

## Notable Changes Since 0.1.2

- Adds canonical match-surface projection support and a static Match Surface
  artifact export path.
- **Breaking for direct artifact readers:** evolves recording/replay surfaces around phase-aware match evidence,
  including the public package shift from broader `turn_index` usage toward
  `phase_index`.
- Adds Archivist Choice behavioral scoring support used by non-combat holdout
  evaluation work.
- Preserves confirmed game context in research package output.
- Updates package metadata and research-package provenance links to the
  renamed private Core repository: `agentdeck/agentdeck-core`.

## Compatibility Notes

- Consumers that read record or replay artifacts directly should audit any
  assumptions about `turn_index` fields and support `phase_index` where emitted.
- Published Agentic Edge artifacts that record `core_version: 0.1.2` remain
  provenance for the historical run environment. New package installs should use
  `0.2.0` for the current Core surface.
- Version `0.1.3` should not be used as a semantic compatibility marker. It was
  a valid package upload, but the version number understated the public delta.

## Release Hygiene

- `0.2.0` intentionally does not add new functional changes on top of the
  already-published `0.1.3` package state.
- After `0.2.0` is available, `0.1.3` should be yanked on PyPI with a note that
  it was superseded by `0.2.0` due to incorrect semantic versioning.
